Forge is an open source source host for people and coding agents changing one codebase at once. Each works in its own Lane; a landing queue checks the exact composed result before it reaches main, and one screen shows who is working, what is changing and what needs you.

What changes from GitHub

Agents keep their editors, their tools and their test commands. What moves is the waiting, the rebasing and the merge queue.

On GitHub today

  • Each agent opens a branch and a pull request, then waits for CI.
  • Every PR runs the full suite on almost the same tree; a four change burst costs 12 checks.
  • Rebases and merge queue retries fall to the agent, or to you.
  • Who is editing what is invisible until the conflict.

In Forge

  • Start a Lane for an Intent, edit its path, run affected tests, finish.
  • Concurrent changes share one landing check on their combined result: 4 checks per burst instead of 12.
  • Updating from main, composition and check scheduling are Forge's job. Accepting never drops another accepted change.
  • Overlaps are raised at save time, as advice, before they become conflicts.

Many agents. One codebase. Nothing lost.

Accepting refuses stale work, main moves only by compare and swap, and a failed check never lands. Those are rules in the code, not promises on this page.

What you get

Nothing lands unchecked, and nothing lands twice
Every acceptance records the exact code it ran on. A failed check comes back to the Lane with the failing test, not a red wall. In 40 overlapping finishes under test, 0 were dropped.
One screen that needs you
Now shows who is working, what is changing, where work overlaps and which one or two decisions are yours. Decisions arrive as questions with answers, recommended one first.
Agents arrive briefed
Copyable prompts and full briefings for nine situations, including fixing a failed check and landing several Lanes together. Prompts tell agents to follow your AGENTS.md or CLAUDE.md first; Forge never overrides a repository's own instructions.
Delegate at the level you choose
Autonomy is a per project policy from supervised to agents accepting on their own, with protected paths and exact View checks. Every automatic action is shown with an auto tag and Undo.
Your repository stays portable
Git repositories work as they are. Accepted source exports to GitHub; native projects need no Git at all. Execution stays on your machines or your own runners.
Built in the open, on itself
Every change to Forge lands through Forge: about 2,200 tests in 315 files, hosted and checked by the same landing queue you would use. What works today is kept current.

How it works

Three commands from an agent's point of view. People do the same from the browser.

  1. Start a Lane for an Intent

    Forge creates an isolated working directory for that one outcome and returns its path.

    nforge agent . start '{"outcome":"fix tax rounding"}'

  2. Edit and save in your own tools

    Claude Code, Codex or an editor works in the Lane. Saves are recorded; overlapping files raise an alert to both parties.

    nforge agent . tests  # affected tests for this Lane's saved head

  3. Finish, and Forge lands it

    Forge updates from main, composes the exact View, runs the check on it and accepts, or hands the decision to you under a supervised policy.

    nforge agent . finish '{"laneId":"…","message":"…","accept":true}'

Where things stand

Forge is in private alpha and builds itself. A public beta is planned.

✓ Works

  • Lanes, exact View checks, landing queue with compare and swap main, accept and revert
  • Git import and export, GitHub publish and one way GitHub sync
  • Hosted projects: Now, Work, Code, Settings, presence, messages, handoffs
  • Agent CLI, MCP and briefings for nine situations
  • Autonomy policy, protected paths, auto tag and Undo

◷ Partial

  • Overlap alerts reach both agents at save time, not always before the next save
  • Clean check environments are not OS isolation
  • Making of record: local owners only
  • Hosted durability: one restore drill passed, no cadence yet

○ Planned

  • Hosted main as the only accept path, then deleting the dual master code
  • Overlap at first write through editor hooks
  • Per Intent contract checks and flake aware culprit finding
  • Public npm release, pricing with a free core, public beta

Questions people ask before trying it

Is Forge faster than Git for a single agent?

No, not yet. In paired single agent trials Forge used 14% more total input and 7% more time than plain Git. Forge's case is several agents landing at once: a four change burst lands 2.2 to 2.4× faster than GitHub's merge queue, with a third of the check jobs.

Do I have to leave GitHub?

No. Git repositories work with Forge as they are, accepted source exports to GitHub, and native GitHub sync fast forwards one commit per acceptance. Your repository stays portable.

Can I use it today?

You can run it from source (Node 24.22.1 or newer, npm ci, npm run verify) and host your own backend. There is no public npm release and no pricing yet; Forge is in private alpha and the team uses it daily on Forge itself.

Where does my code run?

On your machines. Checks run locally or on runners you configure. Hosted Forge stores source and Work; it does not execute your code.

Are checks isolated?

Checks get a clean HOME, temp and environment with an explicit credential passthrough. That is not OS isolation: known absolute files remain readable. Forge makes no claim of confining hostile code. Security has the details.

What does hosting cost?

There is no pricing yet. No cost figures are published until they are measured on real bills.

What happens when two agents edit the same file?

Both get an overlap alert at save time (90 of 90 pairs in the last measurement). Line level three way merge resolves disjoint edits; a true conflict stays explicit in Now and never lands. Accepting never drops another accepted change.
