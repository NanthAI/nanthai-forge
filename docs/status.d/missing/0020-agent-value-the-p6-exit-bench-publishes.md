- **Project deletion.** Owner controls in Settings → General use project ownership independently of Work data. Permanent deletion requires the owner person; `nforge login` device credentials cannot use `nforge host --delete-project`. Deleting a project tombstones it at once: access, grants and runners are revoked; the owner can restore within 90 days (grants not restored); one scheduled call at the deadline, or owner-confirmed **Delete permanently now**, purges every project-owned row, file and R2 object in bounded pages, guarded by a schema inventory test. The R2 part uses a per-project scoped grant (owner-confirmed or expired purge only), never the global `FORGE_R2_MAINTENANCE` flag; pre-inventory tombstones are cleared with the lead's slug-confirmed `repurgeLegacyTombstone`. The CLI reads only the selected project for its current owner and waits on a narrow subscription with zero idle polling calls. See [project retention](../../operations.md#project-retention-and-restore). The CLI can prepare one frozen batch; the owner can review it with a linked Convex Auth session or the existing Clerk sign-in. A hosted run approving ten or more projects together is awaiting verification.
