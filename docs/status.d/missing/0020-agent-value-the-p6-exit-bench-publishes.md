- **Project deletion.** Owner controls in Settings → General use project ownership independently of Work data. Permanent deletion requires the owner person; `nforge login` device credentials cannot use `nforge host --delete-project`. Deleting a project tombstones it at once: access, grants and runners are revoked; the owner can restore within 90 days (grants not restored); one scheduled call at the deadline, or owner-confirmed **Delete permanently now**, purges project-owned rows, exclusive files and unshared R2 objects in bounded pages, guarded by a schema inventory test. The R2 prefix purge stops if its paged reference check finds a foreign-project key or import alias. Legacy purges with incomplete artifact metadata retain possible artifact keys. The R2 part uses a per-project scoped grant (owner-confirmed or expired purge only), never the global `FORGE_R2_MAINTENANCE` flag; pre-inventory tombstones are cleared with the lead's slug-confirmed `repurgeLegacyTombstone`. The CLI reads only the selected project for its current owner and waits on a narrow subscription with zero idle polling calls. See [project retention](../../operations.md#project-retention-and-restore). The CLI can prepare one frozen batch; the owner reviews it signed in to Forge in a browser. A hosted run approving ten or more projects together is awaiting verification.

It reports database reads and requires no snapshot export. See [project retention](../../operations.md#project-retention-and-restore) for coverage and page budgets.
