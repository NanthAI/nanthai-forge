A reply that names a save (`save`, including a settling one, `save --sync`, `land --save` and `recover-apply`) holds only while the checkout equals the head it saved and no local edit was moved out of the checkout; otherwise it fails `UNSAVED_LANE_EDITS` (non-zero exit) naming the files and the one `save` to run. `save --sync` saves before it syncs, so an up-to-date sync leaves nothing unsaved and a clash with main is a conflict to resolve, never a kept-apply copy. A replayed save whose capture the folder no longer matches takes a fresh id. The filesystem-event probe works in the checkout's client cache sibling, so a killed probe never blocks an apply. The check reuses the save's own recorded source walk (Git's untracked cache), so it adds one lstat pass of the saved files, not a second walk; it walks again whenever a directory or ignore file changed. `status {"files":true}` names a save still settling and lists its files as `settling`, not unsaved.

A checkout's sync reply and `nforge status ROOT` show the retained size at 1 GiB and give a command to clear confirmed kept rounds when any exist. Sync can continue, and automatic expiry stays seven days after confirmation.
