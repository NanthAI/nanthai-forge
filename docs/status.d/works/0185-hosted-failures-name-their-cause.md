Every `HOSTED_ACTION_FAILED` names its cause and one next command. `recovery.cause` is a fixed word:
- `server-timeout`, `server-limit`, `server-busy`, `server-exception` or `connection`: the failure happened on the server or the network. These keep the Convex request ID.
- `local-file`, `local-permission`, `local-disk`, `local-process`, `local-exception` or `cancelled`: the failure happened in this CLI, which also writes the stack to the diagnostics log named in the reply.

`recovery.retryable` says whether the same command can succeed. `next` is a wait on the same retained operation, or for preflight the same preflight command. A save, test read or preflight whose failure is transient replays that operation once inside the command, after a short pause. A save that completed therefore answers with its completed receipt, not a failure, and so does the first wait after it. A preflight replays only after a hosted read failed or a lockfile change relinked node_modules. It keeps static checks that already passed for the same head instead of running them again. A transient capability read is no longer reported as `HOSTED_AGENT_UNAVAILABLE`. The tests report read gets the long-action header deadline. The healthy path makes no extra call, and a failure makes at most one replay.
