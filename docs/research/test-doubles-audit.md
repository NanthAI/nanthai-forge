# Test doubles audit

Status: **report only.** No test, source file or check changed. Labels: **M** = measured by reading the files, **E** = estimate, **U** = unrun. Nothing in this page was run: no test, mutation run, build or contract check. It answers Item 5d018d0c, step 1: which tests fake our own code, and what to do about each.

Why it matters: a test that fakes our own server or client passes while the real pair disagrees. Two fixes in November passed every test against fakes and still ended "not verified against the real service" (060fb653, 36fd3295). Each such miss costs a landing.

The biggest single cause is one helper. `tests/hosted-agent-fixture.mjs` answers about 50 server functions by name with hand-written replies. 66 test files reach our server only through it. Rewriting that helper onto real handlers (batch R0) fixes the largest group at once.

Most of the suite already does the right thing. `tests/hosted-fixture.mjs` runs the real `convex/` handlers on an in-memory database and checks every return value against the declared `returns` validator. 585 files fake the Convex runtime this way and nothing of ours.

## What counts as "our own code"

- **Our own code:** the module under test, or any sibling module in `src/` (loaded from `dist/`), `convex/`, `web/`, `netlify/` or `scripts/`. A scripted reply in place of a `convex/` function counts, even when it arrives through a fake Convex client: it replaces our server, not Convex.
- **Outside system:** something we do not write. The Convex runtime (database, scheduler, transactions, storage), R2, GitHub, auth identity, other network services, the clock, the OS (files, processes, streams), the browser, Netlify, Stripe and the MCP SDK.

## Method (M)

A static scanner read every test file and every helper it imports from `tests/`. It never imported or ran repository code. A helper's fakes count for each test that imports it. It flags six kinds of fake of our own code:

| Kind | Rule | Files |
| --- | --- | --- |
| Scripted server | Answers Convex calls by function name (`'module:function'`) without running the real handler | 105 |
| Stand-in object | An object literal passed where our client, transport, store or runner goes (`dispatch`, `call`, `query`…) | 104 |
| Own mock | `mock.method` on a binding imported from our code, a prototype of one of our classes, or an instance built from one | 39 |
| Scripted HTTP | A `fetch` fake answering Forge's own HTTP routes without routing to `convex/http.ts` | 20 |
| Scripted ctx | A Convex action test whose `ctx.runQuery`/`runMutation`/`runAction` returns canned values | 19 |
| Canned branch | Real dispatch, but one function name returns a canned value | 12 |

Not counted as fakes of our code: pass-through spies that call the original, tripwires whose only body is `assert.fail`, and scheduler drivers that route due tasks to the real handler by name. Nine files were hand-corrected after spot checks (for example `r2-read-path` routes its client to the real handler, `account-data` wraps the real query to measure it, `hosted-actions` fakes the GitHub API).

Limits: the scanner works on text patterns, so it can miss a fake built in an unusual shape and can flag a harmless one. The 47 `*` files are the unsure ones; each batch checks its own before rewriting. Outside-system counts include fakes inherited from shared helpers, which is why "auth" is high: `hosted-fixture.mjs` fakes the caller's identity for every hosted test.

## How to fix each kind

Three fixes, in this order of preference:

1. **Use the real module.** Run our code and fake only the outside edge beneath it. This is the default.
2. **Contract fake.** When the real module cannot run in a unit test, keep a fake whose replies are checked against the real module by a named contract suite. Only for our CLI as seen by the bench driver today.
3. **Delete as duplicate coverage.** Only with the proof below.

| Kind | Fix |
| --- | --- |
| Scripted server (client tests) | Route the client's Convex calls into real handlers on `hosted-fixture` state. Build this once as a shared **real-backend bridge** (R0) with the shape of `ConvexHttpClient` (`query`, `mutation`, `action`) and of the React client used by `convex-fake.mjs`. A race the test needs ("main moves just before this call") becomes a real concurrent mutation through the same bridge, not a canned reply. |
| Scripted ctx | Use the `hosted-fixture` ctx, whose `ctx.run*` already runs the real handler and checks `returns`. Inject failures at the database or storage edge. |
| Own mock: runtime seams | `preflightRuntime`, `watcherRuntime` and `diagnosticRuntime` exist only to be mocked (17 files). `filesystemEventHealth(root, execute)` already takes the process runner as a parameter: pass a fake `execute` (OS edge) and delete the seam objects. The watcher seam takes a worker factory and clock instead. |
| Own mock: class methods | `CheckQueue`, `WorkStore`, `NativeSource`, `ImportedPins`, `CatalogTable`, `SelectedRunObserver`, `HostedAgentTransport`, `ActionsJobClient` and others. Build the real state instead (hold the real lock, write the real cancellation), or fail the outside edge (`fs`, `fetch`). Call counting moves to counting outside requests. |
| Stand-in transport or client | The real `HostedAgentTransport` or client over the bridge. |
| Scripted HTTP | Send `fetch` to the real `convex/http.ts` routes on fixture state, as 29 files already do. |
| Canned branch | Keep the real dispatch; replace the branch with real state or an outside-edge fault. |

## Proof before deleting a test

A rewritten test often turns out to cover what a real-path test already covers. Deleting it needs proof (owner decision 2026-11-18, comment 3847e474):

1. **Mutation proof.** Today `FORGE_TEST_SOURCE_PATCHES` mutates only `convex/` modules (through `tests/convex-module.mjs`). Extend the same find-and-replace patches to `dist/` modules with a load hook in `tests/check-runtime.mjs`. Add `scripts/mutate-tests.mjs --module <src file> --candidate <test> --keep <tests>`: it makes mutants of the lines the candidate covers (flip a comparison, negate a condition, drop a call, return early), runs the candidate and the kept tests on each, and writes a receipt. Deletion is allowed when the candidate kills no mutant the kept tests miss.
2. **Coverage does not drop.** V8 line coverage of the module under the kept tests is at least what it was with the candidate.
3. **The Lane says so.** The landing note names each deleted test, the kept tests that cover it, and the mutant counts. The weakened-check detector (f859e277) will flag these Lanes; that is intended.

Likely duplicate clusters to test first: the `hosted-conflict-*` family (files, precheck, reply surfaces, wake, advice, recovery cases, scale, terminal delivery), the `hosted-save-*` family (capture, reliability, settle background, sync efficiency, work stale) and the three `legacy-storage-*` files.

## Guard: refuse new fakes of our own code

A frozen-count allowlist, built the same way as the [test hygiene allowlist](../agents/lint-rules.md#test-hygiene-allowlist).

- **Rule:** `forge/test-no-own-fake` in `scripts/lint/forge-plugin.mjs`. It runs over `tests/**` and `scripts/**/*.test.*`, helpers included. It counts, per file, the six kinds above under keys `ownMock`, `scriptedServer`, `scriptedCtx`, `standIn`, `scriptedHttp` and `cannedBranch`.
- **Allowlist:** `tests/test-doubles-allowlist.json`, one line per file, written once by `node scripts/lint-test-doubles.mjs --init` (refuses to overwrite). A count above the entry fails lint on the extra occurrence. A count below fails too, until `--update` lowers the entry, so the list only shrinks. A file not listed has zero allowance. Raising an entry is a hand edit that the landing note must justify.
- **Not counted:** pass-through spies, `assert.fail` tripwires, scheduler drivers that run the real handler, and dispatch through `hosted-fixture`.
- **Outside fakes name their contract:** each helper that fakes an outside system starts with `// contract: tests/contracts/<system>.contract.test.mjs`. Rule `forge/test-fake-names-contract` fails when the header is missing or the named file does not exist. A new inline `globalThis.fetch` replacement in a test file must go through a named helper; today's inline ones get a frozen `inlineFetch` count in the same allowlist. Clock, file system, process and console fakes are exempt as platform fakes (see open questions).
- **Tests:** `tests/lint-test-doubles.test.mjs` with planted cases in the style of `tests/lint-test-hygiene-plants.mjs`: a new own mock, a new scripted server, a raised count and a missing contract header each fail; a spy, a tripwire and a lowered-and-updated count pass.
- **Cost:** static, no repository code run, about 1 s on a full lint (E), nothing on a preflight that changed no test. Findings name file, line and key only; they never echo source.
- **Starting point (M, files):** 39 own mock, 105 scripted server, 104 stand-in, 20 scripted HTTP, 19 scripted ctx, 12 canned branch. `--init` writes the exact per-file occurrence counts.

## Open questions for the owner

1. **Platform fakes.** Clock, file system, process and console fakes (about 300 files) have no "real thing" to test against: Node is the real thing. Recommendation: exempt them as platform fakes, with no contract suite. Alternative: one platform suite that checks our fault-injection helpers behave like real `fs` errors.
2. **Nightly real runs.** The R2, GitHub and auth suites need a test bucket, a scratch repo with the test App, and a dev test user, plus the secrets on a scheduled runner. Recommendation: yes, on the free public runners, with the cost above. Alternative: run them by hand before each phase close.
3. **Local Convex backend in CI.** Recommendation: use the open-source local backend for the Convex runtime suite ($0 Convex, one binary download a night). Alternative: the dev deployment, which costs database I/O on every run.
