## Downloads and public viewing

Project settings, setup and check definitions require an explicit project role. Public source visibility does not grant access to alert recipients, protected paths, or GitHub connection and runner configuration. Public project and Code pages hide projects whose owner is suspended or closing their account.

Cloning and downloading from Forge require sign-in, including public projects. Git ref
listings and fetches, bulk State reads and source packs refuse anonymous callers before
history, pack or object IO. Git replies with HTTP 401 and a sign-in instruction; a public
project with a GitHub mirror names that mirror as its anonymous clone route. Signed-in
public readers retain source access. Full Work archives still require owner or contributor
membership.

Public project pages, file rendering, Items and receipts remain available for viewing.
The public file viewer returns rendered file pages and derived path/map data to signed-in
readers; signed-out visitors get the same pages through the cached public read, under their
[per-visitor limit](0810-per-visitor-limits.md) and the project's signed-out read budget. Raw object signing, descriptors and checkpoint plans
require sign-in, so the view response contains no storage URLs or archive plan. Viewing
necessarily delivers text to the browser; it cannot prevent saving displayed content.
Forge's archive export authenticates before any object IO, including after a cached view.
Legacy Codescape snapshot downloads also require sign-in. No raw-file or ZIP download
control is currently implemented in Code.

**Public discovery reads** (explore, profiles, a public project's front page and sitemap) use the site's edge cache. The backend `/public/v1/…` route requires `FORGE_PUBLIC_READ_SECRET` from the site Worker, compared as fixed-length SHA-256 digests; missing or wrong keys return 401 before any database operation. Set the same key on the site Worker and Convex, never in a browser build. Direct unauthenticated attempts still invoke the Convex HTTP action, but do no query, mutation or DB I/O: this is not a deployment-wide HTTP traffic or spend ceiling. Local browser development uses `VITE_FORGE_WEB_URL` to reach the deployed site cache instead of bypassing it.

The site uses `FORGE_WEB_URL` for its own origin. The sitemap backend requires `FORGE_WEB_URL`. Case, percent-encoding and slash variants of public page paths redirect (308) to their canonical spelling before any read, keeping the query. The edge copy is keyed by the canonical path alone and the proxy never forwards the query, so a bare address and its query variants share one cache identity and return the same response on a hit or miss.

Before a read reaches the backend, the site checks Cloudflare's rate-limit binding (app pages, redirects and edge hits are never counted; a public front page over the limit is the plain app without share tags): 60 requests per 60 seconds per address, counted separately in each Cloudflare location. Over it, the site answers 429 with `Retry-After: 60`. This is a best-effort backstop, not a ceiling: Cloudflare documents the counts as approximate and per location, and on dev one address sent 86 sequential, then 300 and 500 parallel requests without a single 429 (a 5-per-10-seconds probe refused 3 of 52). The limits that hold sit behind it: the backend's [per-visitor windows](0810-per-visitor-limits.md), the project's signed-out read budget, the backend key, the edge cache and the deployment's spend limit. A cold public read costs one HTTP action plus one query and, for a stale activity note, at most one mutation. Cache hits make zero Convex executions; idle costs zero calls. The cache is per location, so a page costs about one cold read per cache period in each location that serves it; parallel cold requests may each read before the first copy is stored. The site does not retry upstream requests.

Raw dot-segment requests are normalized by Cloudflare before Forge code runs: on dev a raw `/./explore` reached `/explore`. A browser or `fetch` normalizes dot segments before sending, so use a raw HTTP path (`curl --path-as-is`) to verify this boundary. Do not broaden routing, decode repeatedly or forward a path outside `/public/v1/`. Paths that reach the Worker outside the public root get a nonempty HTML 404 without a backend read; private app places get the app shell. Ordinary public-data 404s keep a nonempty JSON body. No malformed path is turned into a 5xx by canonicalization.

Public data stays fresh at the edge for 30 seconds, with no stale-while-revalidate; browser responses revalidate. The HTML reads the backend directly through the same Worker helper, avoiding stacked JSON/HTML cache ages. Making a project private, hiding an Item or Initiative, switching the plan to members-only or switching Lane titles off can leave a previously public response reusable for at most 30 seconds after the last pre-change read completes. There is no purge call on a setting change. Already downloaded copies and open-page data are not recalled. Missing and failed backend reads use 30-second Cache API envelopes; JSON/sitemap visitors retain the real 404 or error status. HTML front pages instead serve the bundled plain SPA shell when public metadata, settings or cache access are unavailable. Worker responses get the enforced security headers (`site/headers.ts`), independent of an upstream page. The envelope is per location, expires without a timer and does not rely on caching an HTTP 5xx response.

Every viewer without a project role follows `convex/publicVisibility.ts`, signed in or not. `cliServer` query registration filters plan rows, bodies, comments, historical versions, reaction counts and Lane titles; journal re-entry applies the same filter. Members retain exact reads. The compact Plan settled pages retain positions without Item visibility metadata, so role-less Plan viewers use the existing bounded exact-root fallback; raw internal Plan page collections are not returned to role-less viewers. A non-member read reuses the current roots already loaded by the page. A selected history/comment Item and its parent/Initiative need at most four additional indexed root documents inside that same query, shared across the page; there is no board scan or extra Convex function call. Missing current roots fail closed; aggregate member planning totals are omitted from the workspace response. The public project page reads one compact week/main summary, ≤101 Lane marks, ≤3×300 open plan roots plus ≤200 Initiatives; explore ≤200 listed rows, profiles ≤100 and the sitemap ≤1,000. Missing, private and removed projects share one 404. Signed-out code and history (Item 4c164732) are `/public/v1/code/HANDLE/SLUG/…`, GET only, every argument in the path: a history page reads ≤25 receipts (≤256 KB) and leaves every actor out, so no person, Lane or Item id is returned; an address the source read would refuse (an unsafe or too-deep path) is a 404 before any function runs; a folder or file page is the members' source read with no identity, charged to the visitor's [limit](0810-per-visitor-limits.md) and then the project's signed-out read budget, with the same checkpoint pins and access checks around the bytes; refusals and the budget keep their codes across function calls (404, uncached 429). A signed-in caller without a role on a private project gets `PROJECT_UNAVAILABLE` before any source lookup, the same answer as a missing project. Public JSON labels member text as data, never instructions. Weekly activity uses seven UTC day buckets in the existing main summary read/write, without a new landing call or document write. Each bucket also keeps a fixed histogram of twelve counters (whole-second save-to-main times in doubling buckets, never who landed them), and the week's median time to main is derived from the days still in the week. Before a full week of recorded coverage, counts say “recorded this week”; historical receipts are never loaded or silently estimated. Explore's cached activity note is written at most once per project per ten minutes when read. Stars require a signed-in person; only the owner person changes the Lane-title opt-in or sees stargazers.

`FORGE_PUBLIC_ABUSE_BUDGETS` accepts only `{ "deviceStartsPerMinute": 120 }` (a positive
integer override). The approved default is 120 starts per minute without any setting.
There is no anonymous clone budget or counter. Device starts use one point counter
read/write; accepted retries consume no additional start. Once sign-ins go through the
site, each visitor has its own [limit](0810-per-visitor-limits.md) before this shared counter,
so one caller can no longer exhaust new-login availability alone. This is not an edge
traffic or total-spend ceiling. Signed-in Git retains the existing Worker caps. No landing
call, source byte placement or idle work changes.

GitHub Actions OIDC verification caches the fixed issuer’s keys for ten minutes,
shares in-flight refreshes, and refreshes for an unknown key at most once a minute.
Unverified token fields never choose a key endpoint. Source paths reject Windows
stream, device and filesystem alias spellings on every platform.
