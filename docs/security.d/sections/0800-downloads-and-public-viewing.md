## Downloads and public viewing

Cloning and downloading from Forge require sign-in, including public projects. Git ref
listings and fetches, bulk State reads and source packs refuse anonymous callers before
history, pack or object IO. Git replies with HTTP 401 and a sign-in instruction; a public
project with a GitHub mirror names that mirror as its anonymous clone route. Signed-in
public readers retain source access. Full Work archives still require owner or contributor
membership.

Public project pages, file rendering, Items and receipts remain available for viewing.
The public file viewer returns rendered file pages and derived path/map data under the
existing signed-out read budget. Raw object signing, descriptors and checkpoint plans
require sign-in, so the view response contains no storage URLs or archive plan. Viewing
necessarily delivers text to the browser; it cannot prevent saving displayed content.
Forge's archive export authenticates before any object IO, including after a cached view.
Legacy Codescape snapshot downloads also require sign-in. No raw-file or ZIP download
control is currently implemented in Code.

**Public discovery reads** (explore, profiles, a public project's front page and sitemap) use the site's durable cache. The backend `/public/v1/…` route requires `FORGE_PUBLIC_READ_SECRET` from the site function, compared as fixed-length SHA-256 digests; missing or wrong keys return 401 before any database operation. Set the same key on the site function and Convex, never in a browser build. Direct unauthenticated attempts still invoke the Convex HTTP action, but do no query, mutation or DB I/O: this is not a deployment-wide HTTP traffic or spend ceiling. Local browser development uses `VITE_FORGE_WEB_URL` to reach the deployed site cache instead of bypassing it.

The site uses `FORGE_WEB_URL` (or Netlify's configured `URL`) for its own origin. The sitemap backend requires `FORGE_WEB_URL`. Case, percent-encoding and slash variants of public page paths redirect to their canonical spelling before any read. The proxy ignores the query string when reading JSON and sitemap data. All HTML, JSON and sitemap responses use one reserved `Netlify-Vary` selector. The handler removes it before a read, preserving other query parameters in the browser. If removing the selector empties the query, the redirect uses an explicit empty entry (`?=`) to prevent Netlify from restoring the original query. Bare addresses and ordinary query variants share one cache identity per path and return the same response on a hit or miss.

The function's native rate rule has a threshold of 60 requests per 60-second sliding window per IP/domain pair, across its routes. It counts requests that would redirect and can replace their 308 with a 429 before the handler runs. This is approximate abuse protection, not an exact request-61 or spend ceiling: [Netlify documents up to ten seconds of enforcement lag](https://docs.netlify.com/manage/security/secure-access-to-sites/rate-limiting/#enforcement-timing). The dev measurement accepted 61 rapid redirects, then returned 429 on the next probe eleven seconds later—about ten seconds of propagation, rather than a redirect bypass. That native block had no `Retry-After` and an empty body. The supported native `rate_limit` configuration has no response-header setting, and the function cannot attach headers to a response that precedes it; Forge adds no counter, storage operation or response handler to change this platform-owned block. Shared addresses share the allowance. A cold public read still costs one HTTP action plus one query and, for a stale activity note, at most one mutation. Cache hits require zero Convex executions; idle costs zero calls. Enforcement lag means 180 executions per nominal threshold, or 360 across two window boundaries, must not be treated as hard upper bounds. The function does not retry upstream requests. The backend key and cache remain separate protections; the dev deployment's spend limit remains the deployment-wide ceiling.

Raw dot-segment requests can be refused before Forge code runs: the dev edge returned an empty 404 for a raw profile/project address containing `/./`, and request detail recorded zero function operations. Forge cannot replace that platform-owned body or add its headers. A browser or `fetch` normalizes dot segments before sending, so use a raw HTTP path to verify this boundary. Do not broaden routing, decode repeatedly or forward a path outside `/public/v1/` to work around the refusal. Paths that reach the function outside the public root get a nonempty HTML 404 without a backend read; private app places retain the SPA shell. Ordinary public-data 404s retain a nonempty JSON body. No malformed path is turned into a 5xx by canonicalization.

Public data stays fresh in the CDN for 30 seconds, with no stale-while-revalidate; browser responses revalidate. The HTML reads the backend directly through the same function helper, avoiding stacked JSON/HTML cache ages. Making a project private, hiding an Item or Initiative, switching the plan to members-only or switching Lane titles off can leave a previously public response reusable for at most 30 seconds after the last pre-change read completes. There is no purge call on a setting change. Already downloaded copies and open-page data are not recalled. Missing and failed backend reads use 30-second Cache API envelopes; JSON/sitemap visitors retain the real 404 or error status. HTML front pages instead serve the bundled plain SPA shell when public metadata, settings or cache access are unavailable. Function responses set the enforced security headers directly, independent of an upstream page. The envelope is regional, expires without a timer and does not rely on caching an HTTP 5xx response.

Every viewer without a project role follows `convex/publicVisibility.ts`, signed in or not. `cliServer` query registration filters plan rows, bodies, comments, historical versions, reaction counts and Lane titles; journal re-entry applies the same filter. Members retain exact reads. The compact Plan settled pages retain positions without Item visibility metadata, so role-less Plan viewers use the existing bounded exact-root fallback; raw internal Plan page collections are not returned to role-less viewers. A non-member read reuses the current roots already loaded by the page. A selected history/comment Item and its parent/Initiative need at most four additional indexed root documents inside that same query, shared across the page; there is no board scan or extra Convex function call. Missing current roots fail closed; aggregate member planning totals are omitted from the workspace response. The public project page reads one compact week/main summary, ≤101 Lane marks, ≤3×300 open plan roots plus ≤200 Initiatives; explore ≤200 listed rows, profiles ≤100 and the sitemap ≤1,000. Missing, private and removed projects share one 404. Signed-out code and history (Item 4c164732) are `/public/v1/code/HANDLE/SLUG/…`, GET only, every argument in the path: a history page reads ≤25 receipts (≤256 KB) and leaves every actor out, so no person, Lane or Item id is returned; an address the source read would refuse (an unsafe or too-deep path) is a 404 before any function runs; a folder or file page is the members' source read with no identity, charged to the project's signed-out read budget, with the same checkpoint pins and access checks around the bytes; refusals and the budget keep their codes across function calls (404, uncached 429). A signed-in caller without a role on a private project gets `PROJECT_UNAVAILABLE` before any source lookup, the same answer as a missing project. Public JSON labels member text as data, never instructions. Weekly activity uses seven UTC day buckets in the existing main summary read/write, without a new landing call or document write. Before a full week of recorded coverage, counts say “recorded this week”; historical receipts are never loaded or silently estimated. Explore's cached activity note is written at most once per project per ten minutes when read. Stars require a signed-in person; only the owner person changes the Lane-title opt-in or sees stargazers.

`FORGE_PUBLIC_ABUSE_BUDGETS` accepts only `{ "deviceStartsPerMinute": 120 }` (a positive
integer override). The approved default is 120 starts per minute without any setting.
There is no anonymous clone budget or counter. Device starts use one point counter
read/write; accepted retries consume no additional start. The global counter remains
shared, so one caller can still exhaust new-login availability. This is not an edge
traffic or total-spend ceiling. Signed-in Git retains the existing Worker caps. No landing
call, source byte placement or idle work changes.

GitHub Actions OIDC verification caches the fixed issuer’s keys for ten minutes,
shares in-flight refreshes, and refreshes for an unknown key at most once a minute.
Unverified token fields never choose a key endpoint. Source paths reject Windows
stream, device and filesystem alias spellings on every platform.
